Oru r01 parser

Implement ORU^R01 intake parsing in Survsys.Messaging. Write Survsys.Messaging/OruR01Parser.cs: a public parser that takes a raw ER7 HL7 v2.5.1 message as text, absorbs the Mirth inbound preprocessing the legacy pipeline performed before nHapi saw a message -- convert escaped newlines (\015) and bare newlines to the CR segment separator nHapi requires, trim surrounding whitespace, and drop the empty segments the documented ARUP cleanup removed -- then parses the result with nHapi's PipeParser as an ORU_R01 message and maps it into the existing Survsys.Contracts intake records: the person from PID (name parts, birth date, birth gender) as a CreatePersonRequest, and the specimen with its tests and results from OBR/OBX/SPM as a CreateLabRequest carrying CreateLabTestRequest and CreateLabTestResultRequest, filling LOINC code, collection and test dates, result value, units, reference range and the coded result from the message and leaving the reference-table ids null exactly as those records document for fields whose lookup tables do not exist yet. Return both in one small result type the parser owns (Survsys.Messaging/OruR01ParseResult.cs). A message that is not a well-formed ORU^R01 -- a missing or wrong message type, or an unparseable structure -- is refused by throwing a parse exception the parser defines (Survsys.Messaging/Hl7ParseException.cs) rather than returning a half-filled result. Keep the preprocessing to what the documented message needs; do not build a per-lab preprocessing pipeline.
