Work Plan

Decide what each Reportability Response asks of this jurisdiction and map its condition codes to the conditions catalogue. Survsys.Data gets two tables with one migration, EcrReportability: ecr_condition_mapping (a code system OID, a code, its display name, and the catalogue condition it maps to, null while unmapped; unique on code system and code), which holds RCTC condition-grouper and SNOMED condition codes alike; and ecr_rr_condition, owned by ecr_document, the RR conditions kept at intake (code system, code, display name, determination code, responsible agency id, reporting timeframe). EcrIntakeOptions gains ResponsibleAgencyIds, this jurisdiction's agency ids as the RR names them (root^extension). A static EcrReportability in Survsys.Api decides each parsed RR condition: it is kept only where its responsible agency is one of those ids and its determination is RRVS1 (reportable) or RRVS2 (may be reportable) -- RRVS3, RRVS4, no determination or another agency is not kept -- and a kept condition is routed 'reportable' when it is RRVS1 and its code maps to a catalogue condition, and 'review' when it is RRVS2 or unmapped; EcrIntakeService stores the kept conditions with each RR. The mapping is resolved when it is read, not when the RR arrives, so mapping a code later takes it out of review. Survsys.Api adds /api/ecr-condition-mappings (list, add, save, delete, and CSV export and previewed import through the existing ReferenceTable/ReferenceImport machinery with columns code_system, code, display_name, condition -- the condition by catalogue name, blank for unmapped), which is how an RCTC release's condition list is brought in, gated as reference data. The eCR queue rows gain a count of conditions routed to review and a filter to RRs that have one; the document detail's conditions gain the mapped catalogue condition and the routing (null for one not kept). Survsys.Web adds the mapping screen with its CSV import and export, a review column and filter on the eCR queue, and the mapped condition and routing on the document screen. Integration tests prove each determination code's routing end to end, and the mapping endpoints, against SQL Server.
