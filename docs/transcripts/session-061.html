Give the case morbidity report the legacy investigation workflow in full. Survsys.Data's WorkflowRules grows from a four-state forward chain to the legacy graph: three more states (not_investigated, approved_by_state, rejected_by_state) and a table of nine named transitions -- accept, investigate, close, route, assign_investigator, do_not_investigate, reopen, approve and reject -- each with the states it is allowed from and the state it moves to, so a move is asked for by transition rather than by target state. Survsys.Data also gains the transition history: a workflow_history table (which report, who, when, which transition, from, to, note), a nullable investigator_id on the report pointing at a user, and one migration that adds both and seeds three new privileges (route_cases, assign_investigators, approve_cases) to the Administrator role. Survsys.Api's PUT /api/person-conditions/{id}/workflow takes a WorkflowTransitionRequest naming the transition, an optional note, the agency a route goes to or the investigator an assignment names; it refuses a transition the report's state does not allow, a caller who lacks the transition's privilege (edit_cases for accept, investigate, close and do_not_investigate; route_cases for route; assign_investigators for assign_investigator; approve_cases for reopen, approve and reject), an agency or investigator not on file; and it writes the state, the agency or investigator, the history row and the notification queue entry in one save. GET /api/person-conditions/{id}/workflow answers with the report's state and investigator, the transitions its state and the caller's privileges allow, and its history newest first, so the Web tier renders what the API hands it and repeats no rule; the old PUT /assignment folds into the route transition, and GET /api/investigators lists the active users an assignment may name. Survsys.Web gives the report a Workflow Options panel offering only the transitions the API lists, with a note box, an agency picker on route and an investigator picker on assignment, and puts the transition history on the Administrative tab; the work queue and the agency board keep their controls and identifiers and send transitions. Survsys.UnitTests proves every allowed and every refused transition of WorkflowRules and the pure rules of the endpoint; Survsys.IntegrationTests proves each transition, the history row each writes, a refused move and a refused caller against SQL Server.
