An integration test carries a staged message through promotion to a case against the shared SQL Server fixture, asserting the report is written with a record number and the message moves to Assigned.

Non-goals:

  • No new staged-message table, column or migration: promotion transitions the existing review-status string column and writes into the existing person-condition tables, adding only a code to the review vocabulary.
  • No automatic promotion: a case is created only from a reviewer's confirmed decision through the promotion endpoint, never derived from the message without human review.
  • No outbound CDC / NMI notification pipeline: notification guides, PHIN variable mapping, rule sets, ORU^R01 generation and direct transmission are Phase 6 (sessions 43 onward) and are out of scope.
  • No e-mail delivery, SMTP, per-condition bn_rules notification configuration or persisted notification log: the batch notification raised at promotion is surfaced to the reviewer, standing in for the legacy batch_notifications e-mail without sending or storing one.
  • No message review Playwright end-to-end tests or walkthroughs: the three Phase 5 walkthroughs and their recorded E2E tests are session 41's work.
  • No change to the authorization rules: the staged-message reads and the promotion write fall under the existing /api fallback policy, so PrivilegeRules is left untouched.
