Work Plan

Session 044 gives the outbound CDC notification half its ruleset engine: the seven NMI ruleset types that turn EpiTrax case data into CDC-coded values, and the dataset repeating groups that let one PHIN variable appear once per lab, vaccine, treatment or travel row. Survsys.Data gains the ruleset configuration storage under the legacy NMI snake_case names, with one migration creating the seven tables -- rule_set (the lookup of the seven ruleset types, keyed 1..7 and seeded with the fixed labels staticValue, cdcFirstSent, cdcDiseaseId, fieldValueMap, conditionMap, notificationStatusResponse and repeatingGroup), rule_set_config (a configuration instance: its format_type, value_set_name and repeating flag), rule_set_field (the EpiTrax fields a config references), rule_set_data (the config's key-value parameters), rule_set_value_map (value_from to value_to translations with an other_specified), rule_set_expression (ordered conditional expressions with a value and an other_specified) and rule_set_expression_condition (the field, operator, value, and_or and value_is_field of a condition within an expression) -- each a bare entity with its internal IEntityTypeConfiguration and a DbSet, every cross-table id left a bare int with no navigation, exactly as the existing reference entities do. Survsys.Messaging gains the evaluation, built over plain in-memory data rather than reaching for a DbContext so the module keeps the fence the architecture test already asserts, referencing neither Survsys.Data nor Entity Framework Core: an in-memory ruleset model, an EpiTrax-record abstraction the formatters read field values and datasets from, a formatted-result container, an expression evaluator that parses conditions into OR-separated AND-groups and compares with the standard operators and the value-is-field flag, a repeating-values helper that returns every formatted response when the repeating flag is set and only the first non-empty one otherwise, and the seven IRuleSetFormatter implementations -- StaticValue, CdcFirstSent, CdcDiseaseId (the placeholder the condition's own ruleset stands in for), FieldValueMap (with its null_value then default_value fallback chain), ConditionMap, NotificationStatusResponse and RepeatingGroup (the placeholder that returns a warning when called directly). Survsys.Messaging also gains the dataset repeating-group processor that, for the Lab, Vaccine, Treatment and Travel datasets, iterates the record's rows and formats each row's PHIN variables once per row. Coded outputs resolve through value-set concept data supplied in the in-memory model, not a database. Survsys.UnitTests gains one test class per ruleset type, each named after the formatter it covers, plus the tests named after the expression evaluator and the repeating-group processor.

Ruleset evaluation core

Survsys.Messaging: the shared evaluation pieces the seven formatters build on, over plain in-memory data so the module keeps its fence against Survsys.Data and Entity Framework Core. RuleSetModel.cs: the immutable records a formatter reads -- a loaded ruleset (its type label, format type, repeating flag, value-set name, and its fields, data parameters, value maps and ordered expressions with their conditions), an EpiTrax-record abstraction exposing field values by name (single or pipe-delimited) and the named datasets (Lab, Vaccine, Treatment, Travel) as rows of field values, a value-set concept (preferred concept name, HL7 code, concept code, code-system OID), and the RuleSetFormattedData result container (value, code, id, code-system OID, other-specified, and an error message with its kind). IRuleSetFormatter.cs: the formatter interface with a method that takes a loaded ruleset, an EpiTrax record and an optional dataset name and returns the formatted results. ExpressionEvaluator.cs: the condition engine that parses an expression's conditions into groups -- an OR starts a new group, an AND continues the current one, all conditions in a group must match and any group matching makes the expression match -- compares with =, <>, >, <, >= and <=, and treats the condition value as another field name when value-is-field is set. RepeatingValues.cs: the helper that returns every formatted response when the repeating flag is set and only the first non-empty response otherwise. Write no formatter and no test in this step; the project compiles.

Ruleset formatters

Survsys.Messaging: the seven IRuleSetFormatter implementations, each a small class formatting one ruleset type over the in-memory model and the repeating-values helper. StaticValueFormatter: outputs a literal from the config's data by format type (string, numeric with validation, date formatted from the current time, or phinValueSet/unitOfMeasure resolved through the supplied value-set concepts). CdcFirstSentFormatter: formats the record's cdc_first_sent_at field, or the current time when it is empty, by the configured date format. CdcDiseaseIdFormatter: the placeholder that returns an informational result noting the condition's own ruleset stands in for it, since it is never driven through the standard pipeline. FieldValueMapFormatter: extracts each configured field, splits pipe-delimited values, and applies the format type, with the null_value then default_value value-map fallback chain and the value-set lookup for coded types. ConditionMapFormatter: evaluates the ordered expressions through the expression evaluator, falls back to the configured default value when none match, and formats the matched value by the format type (text, a value-set lookup, or treating the value as a field name). NotificationStatusResponseFormatter: maps the field's response values through the value map to concept codes and resolves them in the value set. RepeatingGroupFormatter: the placeholder that returns a warning result when called directly, because repeating-group processing is handled by the processor rather than the formatter pipeline. Change no file from the previous step; the project compiles.
