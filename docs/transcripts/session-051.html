Outbreak entities

Add the outbreak domain to Survsys.Data as entities and their IEntityTypeConfiguration files, and nothing of the migration yet. Outbreak is the outbreak record under the legacy outbreak table's columns kept lean: id, number (nullable, as the legacy number VARCHAR), name (required, as the legacy declares it NOT NULL), outbreak_date (nullable), description (nullable), condition_id (nullable FK to conditions, no cascade), agency_id (the owning agency, nullable FK to agencies, no cascade), status (int, default 0) and created_at. OutbreakAccess is the multi-agency grant under outbreak_access: id, outbreak_id (FK to outbreaks, cascade on delete), agency_id (FK to agencies, no cascade) and type (int, default 1), unique on (outbreak_id, agency_id) so an agency is granted once. ReportSection is the seeded reference table under report_section: id and description, seeded with the seven sections the legacy V0003__init.sql inserts in their order (Context/Background; Initiation of Investigation; Investigation Methods; Investigation Findings/Results; Discussion and/or Conclusions; Recommendations for Controlling Disease and/or Preventing/Mitigating Exposure; Key Investigators and/or Report Authors). OutbreakReportSection is the per-section report text under outbreak_report_section: id, outbreak_id (FK, cascade), report_section_id (FK to report_sections, no cascade), user_id (the author) and report_text (nullable), unique on (outbreak_id, report_section_id) so a section is written once per outbreak. OutbreakUpdate is the activity log under outbreak_update: id, outbreak_id (FK, cascade), created_at, user_id, description (nullable) and type (int, default 0). Give PersonCondition a nullable OutbreakId with a FK to outbreaks that does not cascade (a deleted outbreak leaves its cases, setting the column null), configured in PersonConditionConfiguration under the legacy person_condition.outbreak_id column. Register each new entity as a DbSet on SurvsysDbContext. Follow Agency and AgencyConfiguration for the entity-plus-configuration shape, the legacy column names, and the XML-doc grounding in the legacy table and its source file; configurations stay internal sealed.
