Session 81: Connecticut planning regions as county equivalents

*Inserted after session 80. Since 2022 the Census Bureau has counted Connecticut's nine planning regions as its county equivalents (FIPS 09110 to 09190), in place of its eight historical counties (09001 to 09015), and CDC expects the planning region's FIPS code for a Connecticut address. Today the county code list holds only Utah's legacy two-letter codes and "Out-of-state", an address's county is one of those, and OruR01Generator writes that code unchanged into PID-11 for DEM165. A Connecticut zip code can also cross a planning region's boundary, so the zip-to-county table session 69 added cannot fill a region reliably on its own. This follows session 80 because it uses that session's list of the 169 CT towns.*

*Amended before it ran: not every program has moved to the planning regions. ELR and eCR still derive the historical county, not the county equivalent. So a Connecticut address keeps both, and each program is configured to use one or the other. The historical counties stay choosable rather than being refused.*

  1. Register.
  2. Survsys.Data: the county code list carries each value's state, its FIPS code, and whether it is a county or a county equivalent. Connecticut's eight historical counties are seeded as counties and its nine planning regions as county equivalents, each with its FIPS code, and both stay choosable. An address gains a county equivalent beside its county. A ct_towns table maps each of the 169 towns to its historical county and its planning region. One migration adds all of these, changes no existing address, and keeps every Utah code as it is.
  3. Survsys.Api: where the state is CT, a save that leaves an address's county or county equivalent blank fills each one from the town, and fills the county from the zip only when the town gives none.
  4. Survsys.Api: a setting per program — elr, ecr and cdc-notification — names which of the two that program uses, county or county-equivalent. The defaults are county for ELR and eCR and county-equivalent for CDC notification. ELR intake stores the county code a message carries in whichever of the two it names, by the code list, and fills the other from the town. OruR01Generator writes the FIPS code of the one cdc-notification names to PID-11, and the legacy code where the list has no FIPS code. Session 100 reads ecr the same way when it writes an eICR's address to a case.
  5. Survsys.Web: the Demographics tab, the person screen and the case search show the county equivalent beside the county for a CT address. Its label comes from configuration ("Planning region" by default, or "County equivalent"), and every existing element id stays unchanged.
  6. Survsys.UnitTests and Survsys.IntegrationTests: both values filled from a CT town, the zip used when the town is unknown, ELR intake storing a historical county and a planning region each in its own field, PID-11 carrying the configured one's FIPS code under each setting, and the configured label.
  7. Cross-provider verification.
  8. Full test suite, recorded as the run of record.
  9. Close-out.
