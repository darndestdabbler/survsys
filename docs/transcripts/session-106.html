Write the Phase 13 walkthroughs and the Playwright tests that perform them. The E2E intake harness gains the eCR intake: a test-feed drop directory polled every few seconds, this jurisdiction's responsible-agency id, the eCR tables cleared before seeding, and a fixture Fixtures/ecr-intake.sql that maps the walkthroughs' RCTC condition codes to catalogue conditions, puts the patients' zip under an agency, and seeds the person and open case the link walkthrough's eICR names. Small eICR and RR fixture documents derived from the HL7 IG samples are added under Survsys.E2ETests/Fixtures/Cda, one set per walkthrough so each stands alone. Four documents are added to docs/walkthroughs/ and linked from its README, each with the one test named after it in Survsys.E2ETests: review an eICR and its reportability response (drop an eICR and its RR, find them on the eCR queue, open the eICR and read its rendering, the RR's conditions with their determinations, agencies and routing, and the validation findings), map a reportable condition (drop an RR whose condition code maps to nothing, find it under Needs review, map the code to a catalogue condition on the eCR condition mapping screen, and read the condition reportable on the document screen), open a case from an eICR (drop an eICR and RR for a patient not on file, open the eICR and follow its Open case link to the new case, reading its patient and disease), and link an eICR to an existing case (note the record number of a person's open case, drop an eICR and RR for that person and condition, and follow the eICR's Open case link to that same record number).
