Work Plan

Session 037 gives the system its vocabulary matching: the lookup tables that turn the codes a lab message carries into the reference ids the rest of the system means. Survsys.Data gains three reference tables under the legacy EpiTrax snake_case names and one migration creating them -- vocab_master_loinc (a LOINC code to its mapped condition and organism), vocab_master_organism (a SNOMED code to its organism and condition), and vocab_child_loinc (a lab's local LOINC to a master LOINC, the lab-specific override) -- each a bare entity with its IEntityTypeConfiguration and DbSet, with the mapped ids left as bare nullable ints and no navigation, exactly as the existing reference entities do. Survsys.Messaging gains the matcher over that vocabulary, VocabularyMatcher, built so it takes the vocabulary as plain in-memory data rather than reaching for a DbContext -- so the module keeps the fence the architecture test already asserts, never referencing Survsys.Data or Entity Framework Core. The matcher resolves a LOINC code for a reporting lab, letting a lab-specific child-LOINC mapping take precedence over reading the code as a master LOINC, and resolves a SNOMED code to its organism and condition; an unmatched code yields an unmatched result rather than throwing. Survsys.UnitTests gains VocabularyMatcherTests, the tests named after the matcher, covering the master mappings, the lab-specific override precedence, and an unmatched code.

Vocab tables

Survsys.Data: the three vocabulary reference tables the matcher reads, each as an entity with its own internal IEntityTypeConfiguration mapping it to the legacy snake_case table and column names, plus a DbSet on SurvsysDbContext for each. VocabMasterLoinc onto vocab_master_loinc: Id, Loinc (the LOINC code, required), ConceptName (nullable), ConditionId (nullable int, the mapped condition), OrganismId (nullable int, the mapped master organism), OrganismFromResult (bool, whether the organism is taken from the result's SNOMED rather than from the LOINC). Keep every mapped id a bare nullable or plain int with no navigation, as the existing reference entities do, and give each code a sensible bounded length. Add a unique index on each table's natural lookup key: vocab_master_loinc on loinc, vocab_master_organism on snomed, and vocab_child_loinc on (lab_id, child_loinc). Vocab matcher

Survsys.Messaging: the matcher over the vocabulary, taking it as plain in-memory data rather than reaching for a DbContext, so the module keeps its fence against Survsys.Data and Entity Framework Core and references neither. Vocabulary.cs: the input records the matcher reads, each a small immutable record and none of them a Survsys.Data entity -- a master-LOINC entry (the LOINC code, its mapped condition id, its mapped organism id, its organism-from-result flag), a child-LOINC entry (the lab's local code, the reporting lab id, the master LOINC code it resolves to), and a master-organism entry (the SNOMED code, its organism id, its mapped condition id) -- gathered in one Vocabulary container the caller fills from whatever source it has. VocabularyMatch.cs: the small result the matcher returns, carrying the resolved condition id and organism id and whether anything matched. VocabularyMatcher.cs: the matcher built over a Vocabulary, exposing a method that matches a LOINC code for a given reporting lab -- a lab-specific child-LOINC mapping for that lab and code takes precedence over reading the code as a master LOINC directly, resolving through to the master's condition and organism -- and a method that matches a SNOMED code to its master organism's organism id and condition. An unmatched code yields an unmatched result rather than throwing. Write no test in this step.

Vocab matcher tests

Survsys.UnitTests/VocabularyMatcherTests.cs, the test file named after VocabularyMatcher.cs. Build a small in-memory Vocabulary and assert the matcher's behaviour: a master LOINC resolves to its mapped condition, and to its organism where it names one; a SNOMED code resolves to its master organism's organism id and its condition; a lab-specific child-LOINC mapping takes precedence, so the same code reported by that lab resolves through the child to its master rather than by the default master reading; and an unmatched LOINC and an unmatched SNOMED each yield an unmatched result rather than throwing. Change no production code in this step.
