Elr intake service

Add the inbound ELR intake as an IHostedService inside the API tier, the cut session 2 decided, absorbing Mirth's file receipt rather than keeping it. Add Survsys.Api/ElrIntakeService.cs: a BackgroundService that, on each poll of a configured file-drop directory, reads each dropped file and stages it — resolving a scoped SurvsysDbContext through IServiceScopeFactory because it is a singleton — parsing with the Survsys.Messaging OruR01Parser and persisting a StagedMessage in the Entry review state on success and the Exception state carrying the Hl7ParseException detail on failure, then moving the handled file out of the drop so it is not read twice. It has its own per-message timeout, a CancellationTokenSource linked to the stopping token, so one pathological message cannot stall the poller, and it depends on no integration engine. Its options — the drop directory, the poll interval and the per-message timeout — are bound from configuration; with no drop directory configured the service logs once and does nothing, so it is inert for a deployment that has not turned it on and for the existing integration suite. Register it and bind its options in Program.cs, and add the disabled-by-default ElrIntake configuration section to Survsys.Api/appsettings.json. Add Survsys.UnitTests/ElrIntakeServiceTests.cs covering the pure classification of a raw message into a StagedMessage — a parseable fixture to Entry and the malformed fixture to Exception with a detail — over the existing Fixtures/Hl7 messages, named after the service.
