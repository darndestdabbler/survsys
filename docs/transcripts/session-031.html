Work Plan

Give the case morbidity report core element configuration: which of its fields are shown, by default and per condition and per agency, as the legacy Min/Opt Visibility screen did. Survsys.Data gains a core_elements table (legacy core_element: uid, label, plus the tab the field sits on and whether it is hidden by default), seeded by the migration with one row for each field of the Clinical, Investigation and Administrative tabs under a stable uid (the legacy uid where one exists, such as disease_onset_date); a core_element_overrides table that folds the legacy core_element_condition and core_element_agency into one (core element, optional condition, optional agency, hidden), at least one of condition and agency set and one row per combination; and CoreElementVisibilityRules, the pure rule that decides whether an element is hidden for a report's condition and agency, where an agency-and-condition override beats an agency override, which beats a condition override, which beats the element's default. One migration carries the two tables. Survsys.Api adds CoreElementEndpoints: the catalogue with its defaults, setting an element's default, listing, saving and deleting overrides (the condition and agency checked against their tables), and GET /api/person-conditions/{id}/hidden-elements, the uids hidden for that report's condition and investigating agency. Survsys.Web gains a CoreElementsClient, a core element configuration screen reached from the navigation, and the Clinical, Investigation and Administrative tabs leave out every field the report's hidden elements name; a hidden field keeps its stored value, because the tabs still send the whole record. The unit suite proves CoreElementVisibilityRules, the override validator and the client calls.
