Survsys.Messaging gains an outbound generation model -- a notification header (the sending and receiving application and facility as three-part identifiers, the sending time, the processing id, the HL7 version, the profile id and the message control id), a resolved PHIN variable value (its PHIN identifier and display name, its OBX value type, its value, its coded value and code-system OID, its other-specified text, and a sub-id for repeating-group instances) and the generation input that carries the header, the guide profile and the ordered resolved values -- all plain in-memory records so the module keeps the fence against Survsys.Data and Entity Framework Core the architecture test asserts. Over that model Survsys.Messaging gains OruR01Generator, which builds an HL7 v2.5.1 ORU^R01 with nHapi following the legacy NMI segment construction order for the default guide: MSH from the header (MSH.9 fixed to ORU^R01^ORU_R01, the control id and sending time taken from the header so one input generates one deterministic message), PID from the demographic (DEM-prefixed) and death-date variables placed into their named fields per HL7_FIELD_MAPPINGS section 2.2, a single OBR for the default guide (OBR.4 = 68991-9^Epidemiologic Information^LN), and one OBX per remaining resolved variable carrying its identifier, value type and value, then encodes the message to ER7 with a PipeParser. Survsys.Api gains CdcTransmitter, a service that POSTs a generated ER7 message to the configured CDC endpoint over an HttpClient under a configured timeout and returns the transmission outcome -- accepted, rejected, timed out or faulted, with the responding detail and the time it was attempted -- recorded through the logger; its CdcTransmissionOptions bind from a CdcTransmission configuration section that is empty and therefore off by default, as the ElrIntake section is, and Program.cs registers the typed HttpClient and the options. Survsys.UnitTests gains OruR01GeneratorTests, proving the generated ER7 against a legacy generated message fixture for a default-guide case together with the structural invariants of MSH, PID, the single OBR and the per-variable OBX segments; Survsys.IntegrationTests gains CdcTransmitterTests, which stands up a local stub HTTP endpoint on the loopback, points CdcTransmitter at it and asserts the message is delivered and each outcome -- an accepting stub, a rejecting stub and an unresponsive one against the timeout -- is recorded, never reaching CDC.

Direct transmission

CdcTransmitter.cs: a CdcTransmissionOptions (SectionName "CdcTransmission"; an Endpoint string empty by default, which turns transmission off the way an empty ElrIntake drop directory does; a TimeoutSeconds int defaulting to 30); a public CdcTransmissionResult capturing the outcome -- an enum of Accepted, Rejected, TimedOut and Faulted, the responding detail, and the DateTimeOffset it was attempted; and a public CdcTransmitter that is given the typed HttpClient, the options and an ILogger, and whose public Transmit method POSTs the ER7 message body to the configured endpoint under a CancellationToken linked to a timeout of TimeoutSeconds, returning Accepted on a success status, Rejected on a non-success status with the status and body as detail, TimedOut when the timeout elapses, and Faulted on a transport error, logging the outcome before returning it and never throwing.
